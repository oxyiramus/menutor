# Аккаунт и сессия

**Первый выпуск:** 0.3.0 для веб-аккаунтов, 0.3.1 для смены пароля.

Аккаунт отделяет меню, каталоги и покупки одной семьи от данных других пользователей. Регистрация создаёт первый профиль члена семьи, базовые типы приёмов пищи и стартовые категории.

`POST /api/auth/register` проверяет формат email до создания аккаунта и стартовых записей. Ошибка формата возвращает HTTP 422 для поля `email`. Проверка выполняется локально по введённой строке. Адрес сохраняется в исходном регистре, а повторная регистрация с тем же адресом возвращает HTTP 409. Для входа подходят и адреса, сохранённые до введения проверки формата.

Штатный Nginx ограничивает `POST /api/auth/login` и `POST /api/auth/register` отдельно для каждого IP клиента. Для каждого маршрута действует скорость 5 запросов в минуту с `burst=10`. Nginx использует адрес из доверенной цепочки прокси и делит квоту между своими рабочими процессами. Запросы сверх квоты получают HTTP 429 до передачи в backend. Обновление сессии и остальные API-запросы проходят вне этих квот. Штатная схема доступа предполагает, что backend закрыт от прямых публичных запросов.

После входа приложение использует токен доступа и токен обновления. При обновлении сессии выдаётся новая пара токенов, при выходе сервер отзывает переданный токен обновления. Смена пароля доступна в настройках и проверяет текущий пароль.

При регистрации и смене новый пароль должен содержать минимум 12 символов и занимать максимум 72 байта в UTF-8. При проверке пароля учитываются пробелы и исходная форма символов Unicode. Существующий короткий пароль подходит для входа и подтверждения смены. Сервер возвращает `422` при нарушении требований к новому паролю и при вводе более 72 байт в любом поле пароля.

Backend подписывает токены доступа собственным ключом из `JWT_SECRET_KEY`. Для запуска с любой поддерживаемой БД ключ должен быть задан явно. [Настройка ключа](../CONTRIBUTIND.md#локальный-запуск).

При выходе или окончательном отказе обновления сессии интерфейс возвращается к форме входа, закрывает защищённые экраны и очищает загруженные данные аккаунта, выбранные записи, несохранённые черновики и буфер планировщика. Интерфейс отменяет запросы завершённой сессии и игнорирует их запоздалые ответы. При выходе или смене аккаунта открытые вкладки приложения в том же профиле браузера также сбрасывают прежнюю сессию. Настройки отображения сохраняются в браузере.

Завершение сессии распространяется на другие вкладки сразу после выхода. Если в одной из них уже выполнялось обновление токенов, его запоздалый ответ не восстанавливает вход даже до обработки уведомления о выходе этой вкладкой.

Для интеграций профиль доступен через `GET /api/auth/me`. Чтобы изменить отображаемое имя, передайте `nickname` в `PATCH /api/auth/me`. Запрос с полем `password`, включая `null`, возвращает `422` и оставляет профиль и пароль без изменений. Для смены пароля используйте `POST /api/auth/me/password` с полями `current_password` и `new_password`. При неверном текущем пароле сервер возвращает `400`, при успешной смене — `204`. Актуальные схемы доступны в OpenAPI.

**Как пользоваться.** Зарегистрируйтесь, войдите и откройте настройки аккаунта, если нужно сменить пароль. [Первоначальная настройка](../user_guide.md#подготовить-аккаунт-и-каталоги).
