# Доверие к прокси

Схема соединений: внешний TLS-прокси → Nginx frontend по HTTP → Uvicorn по HTTP.
В примере Compose сеть проекта использует `172.29.103.0/24`. Адрес
`172.29.103.2` зарезервирован для TLS-прокси, `172.29.103.3` закреплён за
frontend. Динамические адреса выдаются из `172.29.103.128/25`. При конфликте
подсетей согласованно поменяйте адреса в Compose и в конфигурации Nginx.

Если TLS-прокси используется, подключите его к сети проекта со статическим
адресом `172.29.103.2` и направьте трафик на `http://frontend:80`. Этот адрес
принадлежит только TLS-прокси. Ограничьте доступ на подключение контейнеров
к сети проекта. TLS-прокси определяет схему по своему соединению и IP по
TCP-адресу клиента, перезаписывая `X-Forwarded-Proto` и `X-Real-IP`.
Входящие `X-Forwarded-For` и `Forwarded` он удаляет. Пример этих настроек
есть в [конфигурации TLS-прокси стенда](../../tests/proxy/edge.conf).

Внутренний Nginx сверяет TCP-адрес отправителя с `172.29.103.2` и принимает
от него `X-Real-IP` и схему `http` или `https`. Для остальных отправителей
Nginx определяет адрес и схему по своему соединению. До Uvicorn доходят
заново сформированные `X-Forwarded-For` и `X-Forwarded-Proto`; Uvicorn
принимает их только от доверенного frontend. Прямой HTTP через опубликованный
порт frontend по-прежнему работает.

## Локальная регрессия

Из корня репозитория запустите `sh tests/proxy/run.sh`. Понадобятся
Docker с доступным демоном, Docker Compose и OpenSSL. Подсеть
`172.29.103.0/24` должна быть свободна на локальном Docker-хосте.
Стенд создаёт временный сертификат и собственные контейнеры. База данных,
конфигурация приложения и аккаунты не нужны. Диагностическое ASGI-приложение
подключается только в тестовом Compose. Ожидаемый вывод проверок:

```text
HTTPS через TLS-прокси: https 172.29.103.4
HTTP через TLS-прокси: http 172.29.103.4
Прямой HTTP во внутренний Nginx: http 172.29.103.4
Прямой HTTP в Uvicorn: http 172.29.103.4
```

С установленными зависимостями backend запустите
`python tests/proxy/check_uvicorn.py` для отдельной проверки доверия Uvicorn.
Нужен CLI Docker Compose. Запуск контейнеров и доступ к Docker-демону
для этой проверки не требуются. Ожидаемый итог — `Ran 1 test` и `OK`.
